This documentation describes the current testnet implementation and only publishes facts that are currently configured or deployed.

2. Purchase flow

  1. Connect an EIP-6963-compatible or injected EVM wallet.
  2. Switch to Polygon Amoy.
  3. Enter the desired POL amount and review the estimated RGLM amount.
  4. Accept the Terms & Conditions.
  5. Confirm the transaction in the wallet.
  6. The DApp waits for the receipt and refreshes the RGLM balance.

3. Wallet and network behavior

The MVP supports Polygon Amoy only. The DApp requests network switching and can request network addition when the wallet supports it. Mobile users may open the page inside a wallet browser using the wallet links shown in the connection dialog.

4. Transaction safety

The DApp checks the connected wallet balance, gas estimate and requested purchase value before submitting. It handles wallet rejection, failed receipts, pending receipts and public-RPC failures with visible status messages.

5. Tokenomics publication policy

The website does not invent total supply, allocation percentages or distribution schedules. Those values should be published only after the project team formally finalizes them and they are consistent with the deployed contracts.

6. Swap status

Swap functionality is not enabled because no final swap contract/address has been supplied.

7. Production checklist

  • Complete contract test suite and edge-case testing.
  • Independent security review/audit.
  • Verify final contracts on the relevant block explorer.
  • Confirm ownership/admin controls and emergency procedures.
  • Perform controlled E2E transaction verification with a funded test wallet.
  • Add production monitoring and analytics.
  • Complete final device/browser testing.
  • Publish final tokenomics and legal/compliance disclosures before mainnet.

8. Support safety

Never provide a support representative with your seed phrase, private key or wallet password. Keep transaction hashes for troubleshooting and verify official links before signing.
